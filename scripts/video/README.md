# DUIT walkthrough renderer

This pipeline combines **actual product captures**, reviewed narration, local fonts and small editorial titles. It does not invent app screens, invoke a paid API, generate final speech automatically, or publish videos.

## Review first

1. Review `docs/WALKTHROUGH_STORYBOARD.md` and update `storyboard.mjs` when a final product action differs.
2. Run `node scripts/video/prepare.mjs`. This produces the storyboard document, capture checklist, a capture-manifest example and explicit voice jobs under ignored `artifacts/videos/source/`.
3. Supply real final captures. Generate narration only after review, using the installed AI Voice Generator tool and the exact jobs' arguments. Save each returned native MP3 at the job's file path. Keep tool responses/provenance private with generated artifacts.
4. Save returned native MP3s with `node scripts/video/download-narration.mjs artifacts/videos/source/voice-results.json`. This only downloads jobs already generated by the authorized tool; it creates no provider jobs and reuses matching audio.
5. Run the compositor. It refuses missing voice or product captures. It never substitutes a mock success screen. It extends a scene if necessary rather than trimming speech.

The main cut is planned at 7m45s and the quick cut at 90s. The default AI passage truthfully says the application provider is unconfigured. If a real approved application-AI test succeeds, revise the relevant narration and capture together. Narration generation is separate from the application's paid OpenAI credentials/budget.

## Runtime

Required: Node 20.12+ (tested with 23), ffmpeg/ffprobe including libass and libx264, Playwright plus an installed Chromium. No npm install or manifest change is required in the prepared workspace. The compositor uses a fresh headless browser only to render its local title artwork; it does not drive a user's existing browser profile. The font is local DM Sans; the accompanying `fonts/OFL.txt` licence must stay with the redistributed font.

The renderer looks for Playwright in an explicit `PLAYWRIGHT_MODULE_PATH`, the project installation, then the bundled Codex runtime under the current user's home directory. Supply `CHROMIUM_EXECUTABLE_PATH` when the package's expected browser revision differs from the installed one. The runtime discovery tool identified this machine's working setup:

```sh
export PLAYWRIGHT_MODULE_PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright"
export CHROMIUM_EXECUTABLE_PATH="$HOME/Library/Caches/ms-playwright/chromium_headless_shell-1228/chrome-headless-shell-mac-arm64/chrome-headless-shell"
```

These are runtime environment settings, not changes to `HOME`. On another machine use its installed browser path; the macOS cache revision is not a required dependency. Optional `FFMPEG_PATH` and `FFPROBE_PATH` override executables on `PATH`. The exact font source is the official Google Fonts `ofl/dmsans/DMSans[opsz,wght].ttf`, stored locally as `fonts/DM-Sans.ttf`.

## Proof and final commands

The existing 10-second proof uses the initial real Maya shared-profile screenshot and generated clear-voice narration:

```sh
node scripts/video/render.mjs --cut proof
```

Put final captures in `artifacts/videos/captures/`, or create a private mapping based on `artifacts/videos/source/capture-manifest.example.json`. Each key can map to a local file string or an object:

```json
{
  "maya-today": {
    "capture": "artifacts/videos/captures/maya-today.mp4",
    "start": 0,
    "captureLabel": "Actual app web build · fictional demo",
    "sourceCrop": { "x": 0, "y": 0, "width": 432, "height": 936 }
  },
  "public-profile": {
    "capture": "artifacts/videos/captures/public-profile.png",
    "crop": "top",
    "captureLabel": "Actual mobile web profile · fictional demo"
  }
}
```

PNG/JPEG/WebP stills and MP4/WebM recordings are supported. Video motion is retained once, then the last frame is held. No swipe loop is fabricated. Still captures receive a slow 1.4%-maximum camera move. `crop: top` is available for an initial full-page screenshot proof; prefer final viewport captures. Use focused recordings or browser zoom when desktop text would be too small. Do not override narration or truth labels just to fit an unsuitable capture.

```sh
node scripts/video/render.mjs --cut main --captures .local/video-captures.json --check
node scripts/video/render.mjs --cut main --captures .local/video-captures.json
node scripts/video/render.mjs --cut quick --captures .local/video-captures.json
```

`--audio-dir` and `--out` accept local paths relative to the repository root. All captures are local assets; the compositor does not fetch remote user media. It uses normalized voice audio with an initial pause, 1080p/30fps H.264 video and AAC sound. Rendered output includes MP4 chapters, SRT, Markdown transcript, per-scene clips, title frames and a render manifest. The captions are initially proportional to the spoken words; listen and review timing before delivery.

## Provenance and privacy

The proof narration was generated with the installed AI Voice Generator, voice `clear`, on 18 September 2026. Its full spoken transcript is stored in `storyboard.mjs`. “Do-it” guides spoken pronunciation; “DUIT” remains in captions. It is not cloned speech and uses no borrowed music.

Outputs remain in ignored `artifacts/videos/`. The main and quick videos include privately authorized historical content; they must not be published by this script. Modern demo profiles are fictional. The archive is historical and operator-private. Never record credentials, access tokens, verification codes/links or provider keys. No local outbox screen should imply a real verification email was delivered.

Before final delivery, verify the actual action behind every narration claim, inspect transitions and native capture legibility, listen to the complete voice track, correct captions, confirm dates and data scope, and open the final MP4. A proof render alone does not complete the requested final videos.

## Final capture notes

`scripts/video/capture-web.mjs` records the real browser profile, consented enquiry, verified draft claim, operator scope switch and private archive. It authenticates outside the recorded viewport and masks verification-token and password fields. Its exact fictional fixture rows are removed after capture. Native capture is preferred when available; any Expo-web app footage is labelled **Actual app web build**, never Android. The temporary locked-Mac fallback does not change the product source or simulate successful actions.

For a layout review before every capture is ready, use `--scenes main-05,main-14,main-16`. Partial exports get a `-review` suffix and must not be delivered as the completed cut. Final chapter/SRT offsets use encoded clip durations to avoid accumulated audio-frame rounding drift.
